# План 1 этажа — перевод растрового PDF в DWG

Исходник `План 1 этажа.pdf` оказался **сканом (JPEG)**, внутри PDF нет ни
векторов, ни текста — поэтому «конвертировать PDF→DWG» штатными средствами
нельзя: нужна растровая векторизация. Она выполнена, результат ниже.

## Что получилось

| Файл | Назначение |
|---|---|
| **`План 1 этажа.dwg`** | Готовый чертёж AutoCAD (формат R2000/AC1015). |
| **`План 1 этажа.dxf`** | Тот же чертёж в открытом формате AutoCAD R2010 — «эталонный мастер» (если DWG вдруг капризно откроется — пересохраните DXF в DWG в AutoCAD/nanoCAD/ODA File Converter). |
| **`План 1 этажа — подложка.png`** | Оригинальный растр в полном качестве (150 dpi). В чертеже подключён как подложка (слой `RASTER_UNDERLAY`) — **держите этот PNG рядом с DXF/DWG в одной папке**, иначе подложка не найдётся. |
| `Превью — сверка оригинал-вектор.png` | Картинка «оригинал ‖ вектор» для визуальной сверки. |
| `tools/` | Скрипты, которыми сделана конвертация и проверка (см. ниже). |

## Геометрия и масштаб

- Единицы чертежа — **миллиметры реального здания** (лист начерчен в
  М 1:200 на формате ANSI C 17×22″; пересчёт сделан картографически:
  точная привязка пикселей к пунктам PDF → мм бумаги → ×200).
- Проверка масштаба в AutoCAD: измерьте любой длинный размер (например,
  базовые `21.80`/`22.40` у лестниц) командой _DIST — значение должно
  сойтись с подписью на плане. Если захотите «подкрутить» — используйте
  ALIGN по двум точкам, ориентируясь на подложку.

## Слои

- `A_WALLS` — красные стены: сплошная розовая заливка (HATCH) + красные
  полилинии границ. Толщина 0.35 мм.
- `A_DRAWING` — весь чёрный/серый чертёж: размеры, лестницы, колонны,
  рамка, штамп. Текст переведён в кривые-контура (залитые HATCH) —
  это не редактируемый текст, но **визуально не потерялась ни одна буква**,
  включая любые надписи, которые не читались бы при OCR.
- `A_LITERALS_blue` — синие отметки (`лит.А H=20.03`, `h=3.65` и т.п.).
- `RASTER_UNDERLAY` — оригинал-растр под векторами. Выключайте слой,
  когда подложка не нужна; включайте для сверки.
- `NOTES` — служебная записка о происхождении файла.

## Контроль качества (выполнен автоматически)

- Все 2651 компонент чёрного слоя, 123 компонента стен, 36 синих компонентов
  трассированы; в DXF: **2810 штриховок + 3980 полилиний + 1 подложка**.
- Точечная выборка «внутренних» пикселей масок: **100 %** попадают внутрь
  границ HATCH (заливка в AutoCAD корректна), ложных заливок белых полей —
  **0.000 %**.
- Контуры с самопересечением после упрощения автоматически
  перетрассированы с меньшим допуском (иначе HATCH заливался бы с дырами).
- DWG проверен обратным чтением: все сущности (HATCH/LWPOLYLINE/IMAGE/TEXT)
  переживают конвертацию без потерь; рендер DWG и DXF совпадает
  (различий < 25 пикселей на весь лист — след округления).

## Как повторить/переделать

```bash
python3 -m venv .venv
.venv/bin/pip install pymupdf ezdxf pillow numpy opencv-python-headless
.venv/bin/python3 tools/raster2dxf.py "План 1 этажа.pdf"     # -> DXF + PNG-подложка
# QA-прогоны:
.venv/bin/python3 tools/qa_fill_points.py "План 1 этажа.dxf" "План 1 этажа — подложка.png"
.venv/bin/python3 tools/qa_render.py "План 1 этажа.dxf" /tmp/render.png
# DXF -> DWG выполнен утилитой dxf2dwg из GNU LibreDWG 0.14
```

Параметры конвертации (апскейл, допуск упрощения, отсев пыли, масштаб М)
— в шапке `tools/raster2dxf.py`.

## Ограничения, о которых честно предупреждаем

1. Это **автоматическая** векторизация скана 150 dpi: тонкие штрихи стали
   контурами-полилиниями, а текст — кривыми (не редактируемый). Для «живого»
   рабочего плана дальше обычно обводят нужные стены поверх подложки —
   все привязки уже на месте.
2. Точность исходника — около 2–3 мм на метр (вдоль листа возможны
   геометрические искажения скана ~0.5–1 %). Для обмера БТИ это нормально,
   для генподрядных работ — калибруйте по размерам.
3. DWG создан GNU LibreDWG (открытый кодировщик): открывается AutoCAD и
   nanoCAD; если в вашей версии что-то ругнётся — откройте DXF и
   пересохраните как DWG. DXF-файл является мастер-копией.
